# Roadmap (merged)

Merges the two planning documents: the 18-month enterprise plan (`enterprise_lms_roadmap.md`, six
phases) and the feature audit (`lms-feature-roadmap.md`, priorities P0-P4 and five delivery
phases). Where both describe the same thing it appears once. Status is what the code does today,
verified by the test suites (`npm test`), not what the UI mock-ups show.

Legend: **Done** = implemented and tested. **Partial** = backend done, web screen still sample data.
**Open** = not started.

## Suggested next steps (highest value first)

1. Decide the product domain name, then deploy the production stack with real DNS and certificates (Cloudflare token,
   wildcard record, a test custom domain).
2. Decide trial or paid start; try billing in Razorpay test mode (checkout, webhook, failed payment, grace and suspension) and set the seller's GSTIN and address.
3. Small hardening items are done (HSTS `includeSubDomains` only on our own domains; clamd limits above `UPLOAD_MAX_MB`; file-scan sweep lock).
4. Run the S3 driver against a real bucket, SCORM against packages from Articulate, Captivate and iSpring, and
   virus scanning against a real ClamAV daemon (the Phase 3-4 screens were checked in a browser on 2026-10-18).
5. Try the Copyleaks adapter with a real account (sandbox mode first); try camera proctoring with real webcams and lighting.
6. Switch on the `backup` and `monitoring` profiles on the live server (S3 bucket and write-only key, alert webhook or SMTP, `METRICS_TOKEN`), send a test alert, and run the first restore drill from a dump downloaded from the bucket.
7. Daily digest e-mails and SMS/push channels.
8. Try the DSAR queue and a retention policy with real e-mail delivery and a real storage bucket (tested with a fake mailer and local storage only).
